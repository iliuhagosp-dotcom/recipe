# Blackgram Android — переход на собственную Android-архитектуру

## Выбранный вариант

Blackgram остаётся самостоятельным мессенджером. Аккаунты, сообщения, группы, каналы, файлы и права доступа продолжают работать через Firebase проекта `blackgram-35ecf`. Подключение к Telegram API и MTProto не используется.

## Что берём из Telegram Android

Исходный код Telegram рассматривается как техническая база для изучения и поэтапного переноса отдельных Android-компонентов:

- список диалогов и виртуализированные списки сообщений;
- ячейки сообщений, вложения и просмотр медиа;
- запись и воспроизведение голосовых сообщений;
- системная обработка push-уведомлений;
- разрешения Android, жизненный цикл приложения и фоновые задачи;
- экран звонка и аудио/видеосвязь — после выбора совместимого собственного WebRTC/звонкового сервера.

Компоненты Telegram, которые завязаны на MTProto, номера телефонов, Telegram-аккаунты, Telegram-серверы и Telegram API, не подключаем к Blackgram.

## Целевая схема

```text
Blackgram Android (com.blackgram.messenger)
  ├─ UI Blackgram — сохраняем текущий фирменный интерфейс
  ├─ Android bridge — разрешения, камера, микрофон, файлы, уведомления
  └─ Firebase SDK
       ├─ Firebase Authentication — вход и регистрация
       ├─ Cloud Firestore — профили, чаты, сообщения, группы, каналы
       ├─ Firebase Storage — аватары и вложения
       ├─ Cloud Functions — серверные действия и push-рассылка
       └─ Firebase Cloud Messaging — push-уведомления
```

## Этапы переноса

1. **Android foundation:** закрепить application ID `com.blackgram.messenger`, имя Blackgram, иконки, подпись приложения и сборку APK.
2. **Firebase bridge:** проверить вход/выход, сессию, профиль, Firestore и Storage в Android WebView/нативном окружении.
3. **Чаты:** перенести производительные паттерны списка диалогов и сообщений; сохранить текущую схему Firestore и правила доступа.
4. **Медиа:** системный выбор фото/видео/файлов, камера, микрофон, запись и проигрывание голосовых.
5. **Уведомления:** FCM с корректной регистрацией Android-токена и доставкой при закрытом приложении.
6. **Звонки:** отдельная интеграция WebRTC и сигнализации, не MTProto.
7. **Проверка:** Android 10–15, разные размеры экранов, плохая сеть, повторный вход, фон/закрытое приложение.

## Важное о лицензии исходников Telegram

В загруженном репозитории файл `LICENSE` указывает GNU GPL версии 2 или выше. Если в Blackgram непосредственно копируется или модифицируется код Telegram, нужно соблюдать условия GPL для распространяемой производной программы, включая предоставление соответствующего исходного кода и уведомлений о лицензии. Простое использование общих идей и самостоятельная реализация компонентов не означает автоматического копирования исходного кода.

В README Telegram также указано, что для собственного приложения следует использовать собственные API-данные, не выдавать приложение за официальный Telegram-клиент и не использовать стандартный логотип Telegram.

## Ограничения полученного ZIP

В архиве есть основной Android-проект `TMessagesProj`, но `.gitmodules` перечисляет внешние подмодули (в том числе `td`, `tgcalls`, `libvpx`, `ffmpeg`, `dav1d`, `boringssl` и другие). В ZIP они не включены как полноценные исходники. Поэтому данный архив нельзя считать полностью готовым к воспроизводимой сборке без восстановления подмодулей и собственных Android/Firebase build-настроек.

## Текущая база Blackgram

- Web/PWA интерфейс: `public/index.html`.
- Firebase-конфигурация: проект `blackgram-35ecf`.
- Android wrapper: Capacitor 7, `appId` — `com.blackgram.messenger`.
- Push для Web/PWA: подготовлен в версии 5.3.1; для реальной доставки нужно настроить VAPID и развернуть Cloud Function согласно `README-PUSH-RU.txt`.

## Принцип миграции

Не заменять текущий интерфейс Blackgram Telegram-интерфейсом целиком и не менять Firebase на MTProto. Сначала укрепить Android-оболочку и мост к Firebase, затем переносить отдельные нативные возможности небольшими проверяемыми этапами.
