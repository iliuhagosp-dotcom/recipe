BLACKGRAM 2.2 — ЭТАП 1 (фундамент)

ЧТО ИЗМЕНЕНО
- Список чатов (вкладка «Чаты»): личные, группы, каналы, Избранное; последнее сообщение, время, сортировка по активности. Вкладка «Люди» — прежний каталог.
- Исправлено: у собеседника в личном чате отображалось неверное название (бралось имя из документа создателя чата). Теперь имя определяется по участникам.
- Исправлено: у каналов подпись «Личная переписка»; у только что созданной группы не было списка участников.
- Ответы на сообщения (цитата, переход к исходному по нажатию).
- Редактирование (только свои текстовые, с пометкой «изменено») и удаление своих сообщений.
- Реакции по пользователям: одна реакция от человека, повторное нажатие снимает, счётчики. Старые реакции (массив) показываются как раньше.
- Сообщения обновляются по одному, а не перерисовываются целиком: сохраняется прокрутка и плеер голосовых.
- Разрешения микрофона и камеры добавляются в Android (AndroidManifest) и iOS (Info.plist) шагами в workflow.
- Файл firestore.rules — черновик правил безопасности (см. ниже).
- Версия 2.2.0, кэш service worker v21, обновлён blackgram-release.json.

КАК ОБНОВИТЬ GITHUB
1. Распакуй ZIP. Загрузи содержимое папки recipe-main в корень репозитория с заменой файлов (включая папку .github/workflows).
2. Commit changes в ветку main — APK соберётся автоматически (Actions → Build Blackgram APK).
3. Скачай артефакт Blackgram-debug-apk, установи, проверь.

FIRESTORE RULES (делай осторожно)
firestore.rules НЕ применяется автоматически GitHub Actions. Правила не проверялись на эмуляторе Firebase.
1. Firebase Console → Firestore Database → Rules: скопируй текущие правила в запасной файл.
2. Вставь содержимое firestore.rules, проверь в Rules Playground (вход, открытие чата, отправка, реакция, звонок) и только потом Publish.
3. Если что-то сломалось — верни сохранённые правила.
Без новых правил редактирование, удаление и реакции зависят от ваших нынешних правил: если они запрещают обновление и удаление сообщений, вы увидите сообщение об ошибке.
Ограничения правил: заблокированного пользователя правила не отключают (блокировка работает на клиенте); адреса почты всех пользователей по-прежнему читаемы всеми авторизованными (будет решаться в этапе приватности).

ПРОВЕРЕНО
- Синтаксис JS-модуля (node --check), YAML обоих workflow, JSON-файлы.
- Шаг workflow с разрешениями Android выполнен на тестовом манифесте.
- Чистая логика (счётчики реакций, названия чатов, формат времени) прогнана тестом.
НЕ ПРОВЕРЕНО (нет сети, браузера и устройств в среде разработки)
- Работа с реальным Firebase, интерфейс на телефоне, сборка APK/iOS в GitHub Actions, шаг PlistBuddy, правила Firestore, микрофон и звонки на устройстве.

ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ ЭТАПА 1
- Превью последнего сообщения в списке не обновляется после редактирования или удаления.
- Счётчика непрочитанных нет.
- Исправления звонков (гонка кандидатов, повторная обёртка endCall, TURN) не вошли в этап 1.
- Фото/файлы, поиск по сообщениям, push-уведомления — этапы 2–3.
